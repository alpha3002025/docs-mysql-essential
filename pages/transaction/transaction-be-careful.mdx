## 트랜잭션 사용시 주의점

트랜잭션은 하나의 커넥션 또는 세션 위에서 수행되는 작업 단위입니다. 트랜잭션이 길게 늘어져서 오랫동안 자원을 점유한다면 Database 의 동시성 성능을 저하시키는 요인이 됩니다.<br/>

따라서 하나의 트랜잭션 단위에서 너무 많은 연산을 수행한다거나 오래 걸리는 작업을 수행하지 않도록 주의가 필요합니다.<br/>

트랜잭션이 오래 유지되면 커넥션을 오래 점유할 뿐만 아니라, lock 유지 시간 증가, MVCC 를 위한 오래된 row version 또는 undo log 정리 지연, deadlock 가능성 증가 같은 문제가 함께 발생할 수 있습니다.<br/>

특히 외부 API 호출, 파일 업로드, 메시지 발행, 긴 계산 작업처럼 Database 작업이 아닌 오래 걸리는 로직은 가능한 한 트랜잭션 밖에서 수행하는 편이 좋습니다. 꼭 함께 처리해야 하는 경우라면 트랜잭션 경계를 의도적으로 짧게 나누거나 실패 보상 로직을 별도로 설계해야 합니다.<br/>

배치나 일괄 정산 작업 등을 뒷단에서 수행하는 서비스를 운영하는 것이 아니라면 가급적 트랜잭션은 짧게 가져가는 편이 좋습니다.<br/>
