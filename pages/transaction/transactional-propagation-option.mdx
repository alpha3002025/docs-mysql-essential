## 트랜잭션 전파 옵션

트랜잭션 전파 옵션은 여러가지가 있습니다. 그 중 가장 많이 쓰이는 것은 `REQUIRED`, `REQUIRES_NEW` 입니다. 이 외에도 여러가지 전파 옵션이 있는데, 특수한 케이스에 대해 대응 방안이 될수 있도록 하기 위해 여러가지 트랜잭션 전파옵션들을 간략하게 정리해봅니다.<br/>



### REQUIRED

가장 많이 사용하는 기본설정입니다. 기존 트랜잭션이 없으면 생성하고 있으면 기존 트랜잭션에 참여합니다.<br/>

- 기존 트랜잭션 없음 : 새로운 트랜잭션을 생성합니다.
- 기존 트랜잭션 있음 : 기존 트랜잭션에 참여합니다.

<br/>



### REQUIRES_NEW

기존 트랜잭션에서 파생되었더라도, 또는 합류할 기존 트랜잭션이 있더라도 항상 새로운 트랜잭션을 생성합니다.

- 기존 트랜잭션 없음 : 새로운 트랜잭션을 생성합니다.
- 기존 트랜잭션 있음 : 기존 트랜잭션을 잠시 보류하고 새로운 트랜잭션을 생성합니다.
  - `REQUIRES_NEW` 를 사용할 때에는 새로운 트랜잭션에 참여 했음에 유의해서 봐야 합니다. (같은 트랜잭션으로 처리되지 않고 개별 트랜잭션으로 처리됩니다.)
  - 외부 트랜잭션과 내부 트랜잭션이 서로 다른 커넥션을 사용할 수 있으므로 커넥션 풀 크기에도 주의해야 합니다.

<br/>



### SUPPORTS

트랜잭션을 지원한다는 의미입니다. 기존 트랜잭션이 없으면 없는 대로 진행하고 기존 트랜잭션이 있으면 참여합니다.

- 기존 트랜잭션 없음 : 트랜잭션 없이 진행합니다.
- 기존 트랜잭션 있음 : 기존 트랜잭션에 참여합니다.

<br/>



### NOT_SUPPORTED

트랜잭션을 지원하지 않는다는 의미입니다.

- 기존 트랜잭션 없음 : 트랜잭션 없이 진행합니다.
- 기존 트랜잭션 있음 : 트랜잭션 없이 진행합니다.(이미 있는 기존 트랜잭션은 보류합니다).

<br/>



### MANDATORY

의무사항입니다. 트랜잭션이 반드시 있어야 합니다. 기존 트랜잭션이 없으면 예외가 발생합니다.

- 기존 트랜잭션 없음 : `IllegalTransactionStateException` 예외가 발생합니다.
- 기존 트랜잭션 있음 : 기존 트랜잭션에 참여합니다.

<br/>



### NEVER

트랜잭션을 사용하지 않는다는 의미입니다. 기존 트랜잭션이 있으면 예외가 발생합니다. 기존 트랜잭션도 허용하지 않는 강한 부정의 의미로 이해하면 됩니다.

- 기존 트랜잭션 없음 : 트랜잭션 없이 진행합니다.
- 기존 트랜잭션 있음 : `IllegalTransactionStateException` 예외가 발생합니다.

<br/>



### NESTED

중첩 트랜잭션은 기존 트랜잭션이 있을 때 savepoint 를 만들어 부분 롤백이 가능하도록 하는 방식입니다.

- 기존 트랜잭션 없음 : 새로운 트랜잭션을 생성합니다.
- 기존 트랜잭션 있음 : 기존 트랜잭션 안에 savepoint 를 만들고 중첩 트랜잭션처럼 동작합니다.

기존 트랜잭션이 실패하면 내부에서 수행된 작업도 함께 롤백됩니다. 내부 작업이 실패했을 때는 savepoint 까지만 롤백하고 외부 트랜잭션을 계속 진행할 수 있지만, 예외가 외부로 전파되거나 외부 트랜잭션이 rollback-only 로 표시되면 전체 트랜잭션이 롤백될 수 있습니다. 또한 `NESTED` 는 사용하는 TransactionManager 와 데이터베이스의 savepoint 지원 여부에 영향을 받습니다.<br/>
